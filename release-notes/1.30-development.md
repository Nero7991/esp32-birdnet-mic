# 1.30 development and validation record

These are development records retained from the local 1.27 cycle, not claims of fresh
1.30 hardware testing. PDM remains experimental; final release preparation checks are recorded separately.

## Development changes

### Microphones and audio

- Add PDM microphone selection for IM73D122 on XIAO ESP32-C3/S3/C5/C6, based on Dan Logue's v15.6 contribution. S3 uses hardware PDM-to-PCM; C3/C5/C6 use an integer software decimator. PDM outputs mono 48 kHz PCM with a 3.072 MHz clock; Gain and HPF remain available, while I2S Shift applies only to I2S microphones. Philips I2S remains the default.
- Detect paired/plain raw PDM slots from their arrival rate, including IM73D122 data whose paired slot values need not match. Start in paired mode on C3/C5/C6, exclude startup backlog and DMA-overrun windows, retry ambiguous measurements, and detect bit order from the microphone signal. Preserve byte/pair phase across short or timeout reads, reset detection on reconfiguration, and keep capture interruptible for OTA/settings changes.
- Replace per-sample floating-point gain/HPF processing with Dan's integer stage for all boards and microphone paths. Safely widen S3 PDM samples into the common PCM layout. The producer owns filter state and applies live HPF changes between blocks, using configuration snapshots to notice subsequent edits.
- Stop capture before changing microphone format or audio parameters. Roll back format, rate, gain, packet size, shift, HPF cutoff and automatic recovery threshold as applicable if reconfiguration fails.
- Adapt the audio ring-buffer reserve to available internal RAM and the largest free block. Retain 80 KiB for Wi-Fi/TCP plus producer-stack/allocation headroom, keep at least four chunks or 16 KiB, and reject unsafe allocations. Recommend 512 samples on C3/C5 through the API/UI without overwriting saved packet sizes; keep the full reserve on C6/S3 when memory permits.

### Browser listening and microphone health

- Add Listen/Stop in the header with an explicit 0–100% playback-volume control; 100% uses full browser gain without changing microphone Gain. Listen receives the same processed PCM as RTSP, including Gain and HPF, for supported I2S and hardware/software PDM paths at the active sample rate.
- Serve a separate bounded HTTP WAV preview on port 81 without consuming RTSP client slots or the RTSP audio reserve. Reject a second listener, close slow connections, and restrict cross-origin access to the matching device page.
- Stop preview on hidden/closed pages, audio reconfiguration, server OFF, scheduled/thermal shutdown, Wi-Fi reconnect and OTA; support stopping and reconnecting from the browser.
- Detect 20 seconds of unchanged raw I2S or decoded PDM PCM before user gain/shift/HPF. Report checking/OK/flatline/unavailable in the header, Stream health, API and MQTT; clear the warning when signal variation returns without resetting capture.

### Web UI and settings

- Organize controls into nine independent sections, collapsed on fresh load. Add a Listen header with responsive microphone, stream, Wi-Fi and temperature tiles plus audio level, sample rate, RTSP client count and uptime. Keep microphone/thermal warnings visible above collapsed sections.
- Preserve section expansion and unsaved edits during polling. Add save/discard feedback, report save errors, protect edits made while a request is pending, and confirm factory reset. Mark stale device data when refresh fails.
- Put essential audio/thermal settings first and advanced audio controls together. Move the RTSP client limit to Streams, I2S Shift to Audio, Wi-Fi transmit power to Network, CPU frequency to Thermal management, and warning check interval to Recovery & Maintenance. Remove the unsupported 120 MHz CPU choice.
- Group MQTT connection, publishing and discovery settings; validate and save the complete MQTT broker connection or streaming schedule in one request. An empty MQTT password retains the saved value; clearing it is explicit.
- Explain waiting, scheduled and thermal stream states. Label packet duration separately from total listening delay, make help keyboard-accessible, stack fields on narrow screens, show full microphone names, and preserve PDM-specific controls and restrictions.
- Correctly display 0 dBFS at full scale instead of -90 dBFS.

### Thermal protection and recovery

- Add optional automatic RTSP recovery after five continuous minutes at least 15 C below the shutdown limit; disabled by default. Respect stream schedules and an explicit server stop.
- Block automatic recovery after the third shutdown in a rolling 24-hour window until acknowledged after cooling. Emergency shutdowns require immediate manual acknowledgement. Persist history and lockouts across reboot; restart cooling timers after reboot or invalid/stale sensor readings.
- Show cooling progress, the 24-hour shutdown count and a prominent warning that remains after automatic recovery until acknowledged. Acknowledging an active shutdown starts a new retry series; acknowledging a recovered warning preserves the count. Retain last-shutdown details after acknowledgement.

### Diagnostics, reliability and MQTT

- Use matching atomic 32-bit reads/writes for the audio ring-buffer drop counter across capture, RTSP recovery and the Web UI, resolving the declaration mismatch and C++20 volatile-increment warning.
- Report estimated audio-processing load over two-second windows with a peak since capture started, including software PDM conversion time and excluding blocking microphone reads. Warming-up, stopped or stalled capture reports unavailable values; this is not total CPU utilization.
- Count I2S receive DMA overruns through a bounded ISR protected by a critical section. Exclude reconfiguration, report total and sampled last-minute counts separately from RTSP/ring-buffer drops, mark failed callback registration unavailable, and limit repeated warnings to once per minute.
- Expose PDM capability, decoder, clock, confirmed word stride and bit order, the integer DSP path, recommended packet size and actual ring-buffer capacity through the audio API. Keep diagnostics in Stream health.
- Build Home Assistant discovery from a shared entity table while preserving all 32 payloads, entity IDs, topics, cleanup steps and paced/retried publication. Construct only the command topic required by the current entity.

### OTA and build

- Fix manual OTA upload by capturing the selected firmware in FormData before disabling controls. Validate against the actual next app partition size without subtracting an extra 4 KiB; reject missing partitions, oversized images and merged USB firmware.
- Serve OTA CSS/JavaScript as separate gzip assets. Share field-refresh logic, render fixed English labels directly, minify CSS/JavaScript with pinned tooling, and generate deterministic compressed assets with Zopfli while preserving OTA progress, upload protection and reconnect behavior.
- Enable LTO automatically for C3/C6 through the shared compile helper and CI, with isolated Arduino core builds to avoid mixing compiler flags. Keep normal S3/C5 compiler settings. Direct Arduino IDE/CLI builds that bypass the helper do not automatically enable LTO.
- Retain existing partition tables, app-only OTA format, board-specific filenames, automatic update URLs and C6 compatibility aliases. Updates require no repartitioning or USB migration.

### Validation and current limits

- Final C3/S3/C5/C6 builds pass with Arduino-ESP32 3.3.12; packaged web/manual OTA images match their build outputs. The C6 app image is 1,276,800 bytes with 33,920 bytes free in its existing OTA partition; C3 has 48,144 bytes free.
- 40 Python/native regression tests pass, including integer-DSP reference comparisons, PDM response/bit-order/rate detection, constant and unequal-slot data, short/timeout reads, DMA-overrun handling, memory limits, transactional rollback and microphone/preview integration. All 32 MQTT discovery payloads retain their previous contents. Thermal/ISR failure paths were exercised with simulated inputs; physical overheating was not induced.
- Source and embedded-page browser checks pass for collapsed sections, draft/save behavior, invalid/unauthenticated grouped requests, PDM controls, warnings, stale data, keyboard/mouse/touch volume controls, light/dark themes, 320–1280 px layouts and OTA assets. Local manual browser-file OTA was also exercised during development.
- Final local C6 OTA preserves all 36 checked settings and serves the exact generated UI. Live HPF changes apply during capture and restore correctly. A final test of at least 60 seconds of simultaneous TCP/UDP RTSP and 48 kHz browser audio delivers about 93 packets/s on each RTSP stream without new I2S errors, DMA overruns, ring drops, RTSP write timeouts/failures or JavaScript errors. Original stream/preview state is restored afterward.
- On this C6 with its existing I2S microphone, measured audio-processing load falls from about 24.8% to 5.3%. This is a short local measurement, not a long-duration stability or PDM performance guarantee.
- Dan reports physical PDM tests on all four boards with his v15.6 firmware. Our integrated PDM image still requires physical microphone/audio validation on each board; sustained C3/C5/S3 validation remains pending. These tests preceded release preparation.
