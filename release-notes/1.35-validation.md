# v1.35 validation

The first automatic update from older firmware installs the small v1.35 bridge. On stock XIAO C3/C6 devices, open **OTA update → Prepare device**, confirm once and leave power connected. Copying, restarts and reconnection happen automatically; saved settings are retained. Further OTA updates become available after preparation. S3/C5 do not need this step.

The old update addresses permanently serve the frozen bridge. Prepared firmware uses `/updates/` for current releases. An older device that skips releases therefore still receives v1.35 before a future larger image. Explicit manual versioned downloads remain the user's responsibility: install the bridge first on an unprepared device.

## Checks completed on 2026-10-24

- C3, S3, C5 and C6 builds passed. Each bridge image fits its original OTA slot. The release C6 app is 1,295,104 bytes, below the original 1,310,720-byte limit.
- 75 host tests passed, including migration from both old slots, pending migration across reboot, settings preservation, invalid/read-failing tables, stale SDK descriptors, failed writes, restoration and retry. HTTP tests cover old v1.34 accepting the bridge and v1.35 enforcing preparation before automatic/manual flash writes; ArduinoOTA also respects the gate.
- Eleven preparation browser scenarios passed, including confirmation, cancellation, rejected requests, lost responses, reload/reconnection and timeout/retry. Existing OTA and responsive UI checks passed.
- A real nginx test used the production routing configuration with simulated v1.40 images larger than the old slots. Every legacy board URL still delivered the small v1.35 bridge; `/updates/` delivered v1.40. Packaging and publication tests reject changed bridge hashes and an oversized initial bridge.
- The owner completed automatic OTA and **Prepare device** on the physical C6 during development. The final release was subsequently installed on that prepared C6.
- A deliberately enlarged 1,704,944-byte test image successfully installed and booted on the C6. A test-only endpoint confirmed that it actually ran. The exact release image was then restored. All 35 compared settings were retained through these updates; the reported slot capacity was 2,031,616 bytes.
- Real browser listening and RTSP/TCP and UDP reception passed on the release image. The UDP check temporarily enabled the second stream and restored it afterward; all 35 compared settings matched again. Capture remained active without reported I2S errors. The device used I2S for these checks.

Release C6 SHA-256: `3e94ecda8852adb04f097c942f61367bd1b17142d8008f98170b713763249d2f`.

## Limits

Physical C3 migration and destructive power-loss tests were not performed. Host fault injection cannot prove recovery from every interruption. Losing power during the partition-table erase/write can require USB recovery; keep power connected throughout preparation. Custom or unsupported layouts are not automatically rewritten.

The maintainer separately reports excellent sound and no audible noise from the newly received PDM microphone. This listening result is not a measured SNR or long-running qualification of every board/microphone combination.
